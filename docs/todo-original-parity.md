Baseline: main `716db5d231a420449c0586ec64ba96053e4b4179`. Sources: `todo/index.html`, `todo/todo.js` and `todo/todo.css`; existing `readTodo`, `writeTodo`, `cloneTodo` in `worker/src/index.js` (5441–5680). Existing pages and APIs remain available. ## Source semantics retained

- Quick capture: required title, first category or その他, no role/deadline/priority, progress zero, pending. Destination inbox (default), today or tomorrow in JST; no automatic deadline. Successful creation clears filters and refocuses capture.
- Original hierarchy is a flat task array plus independent roles, categories and ordered checklist steps. There is no task parent/child tree, task drag/reorder, category-tree depth, manual task sort or task archive control. Do not invent any of these and call it migration. Roles archive/resume; tasks delete after confirmation; completion remains a record.
- Date list: today/past focus (up to three important/high-priority tasks first, stable original order), today's remaining, future days ascending, unscheduled inbox, completed records. Board has pending/doing/waiting/done columns in that order. Original task array order is preserved inside grouping; categories alone have explicit up/down ordering.
- Search title/memo/reusable-description case-insensitively; role and category intersection; clear filters/count. Deadline guardrail deliberately ignores these filters and includes all non-done tasks overdue or within seven days, sorted by deadline. No browser filter persistence existed; shell-session persistence retains filters and mode across native detail routes without creating a new cross-device setting.
- Detail: title, role (archived role retained if already assigned), category, planned day and independent deadline, status, optional priority 1–3, important flag, private memo, reusable description, checklist add/check/remove (max200, stable IDs). IME Enter must not append a step. Saving uses original trim/null semantics. Changing status resets progress to100/0 and completedAt; unchanged status preserves legacy fractional progress. Other task fields and clone receipts are preserved.
- Card completion/reopen updates status/progress/completedAt; plan-today only changes plannedDay. Neither rescheduling nor carry-over changes deadline. No workflow execution/claim is involved.
- Roles: name/icon/color, add/edit/archive/resume; no removal of historical roles. Categories: add/rename/order/delete; rename updates assignments, used-category deletion requires chosen target and explicit confirmation; sole used category cannot be removed.
- Clones: direct1/3/7/14 days, custom days/weeks1–3650, preview in JST. Deadline defaults to none, explicit copy button. New task resets completion/step checks, copies reusable description rather than old private memo, preserves only server-approved references. Original remains unchanged. Durable original per-request localStorage keys shared with old page; GET receipt before any idempotent POST, unknown result retained through reload, same request ID recovered, receipts preserved by server CAS. Storage failure prevents dispatch. No automatic recurring tasks.
- Native stable `/app/#!/todo/:id/` detail route supports reload, Back/Forward and explicit close; existing `/todo/` untouched. Modal Escape/cancel/focus plus shell unsaved and busy guards protect input. Role/category dialogs stay within current route; shell Back applies the same unsaved guard. Initial fetch makes no writes. Auth/session teardown aborts requests and fences delayed responses.

## Safety additions relative to original

A failed/unknown whole-document PUT never auto-refreshes the editing revision or permits another stale mutation. Inputs/revision remain visible, edits freeze, explicit GET inspection does not unlock/replay; confirmed discard/reload obtains a fresh snapshot. Both list and modal recovery include draft export, including disabled input values. Successful response must match sent tasks/categories/roles and advanced revision. Destructive task/category actions retain explicit confirmation. No production data operations are used as tests.
