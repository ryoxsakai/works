# 共通アプリ枠＋SS・第1段階

## 今回の変更

- 新しい独立入口 `/app/`。既定の `/`、旧 `/ss/`、他機能の入口は切り替えない。
- スマホは下部5分類、PCは左ナビ＋SS一覧／詳細。未統合機能は従来画面を別タブで開くと明示する。
- SSは**現行と同じ閲覧専用**。実際の `GET /api/ss-projects` を既存のWorksセッションで読む。試作データ、架空の進捗率、試作メモ保存は本番用入口で使用しない。
- 旧SSと同じ完了表示・案件名／状態／締切／残り期間の並べ替えと方向を保持。既存 `works_ss_sort` の設定を共有する。検索・選択はメモリとURLに保持し、案件内容をブラウザ保存しない。
- 旧SSへのリンクと旧ホームへのリンクを残す。旧SS・API・DB・承認／割り当て／実行権は変更しない。

## 認証・失敗時

既存 `/shared/auth.js?v=12` を同じURLで1回だけ初期化する。Google認可は既に使用している `/tutor/` に戻し、既存の `works_pending_destination` に**厳密な `/app/` のみ**を追加。OAuth URI登録やスコープ追加は不要。詳細URLへの復帰は検証済みルートだけをsessionStorageに一時保存し、復帰時に消費する。認証情報は新たに複製保存しない。

401／403、別タブでの認証変更、ログアウトでは表示済みの案件DOMを破棄し、進行中リクエストを中断する。JSON読込中のセッション変更も世代番号で遮断する。ブラウザの戻るでも消した案件を復活させない。BFCacheからの復帰は再読み込みして認証を確認する。

409／429／5xxは表示上の失敗として明示し、ユーザーの再試行以外で自動再送しない。SSに書き込みUIを足していないため、既存MCP側のrevision・更新権限・競合処理を迂回する経路はない。ログアウト処理だけが既存認証の失効APIを使用する。

## 構成・配信

- `prototype/shell-app.mjs`：共通枠。Framework7 Core 9.2.0＋Panel、Reactなし。
- `prototype/production/main.mjs`、`context.mjs`：本番用認証・GET API・セッション破棄。
- `prototype/ss-module.mjs`：root限定の描画とAbortController付きイベント、終了後の応答破棄。
- `prototype/navigation-guard.mjs`：単一ViewのBack／Forward位置を補正する既存試作のアダプター。F7の公開router APIを使用し、第二のルーターは追加しない。
- `/prototype/` は引き続き合成データの試作。`?fixture=` などの試験スイッチは `/app/` では使用しない。
- `app/index.html` と `app/assets/*` はViteから生成した**追跡対象の静的配信ファイル**。既存の静的ホスティングでnpmビルドが必要にならないようにする。CIで再ビルド一致を必須にする。生成先以外の既存ファイルはビルドで消さない。
- DB移行、Worker本体の変更、新しい資格情報、課金ライブラリは不要。依存は試作の固定バージョンとlockを継続利用する。

```sh
npm ci --prefix prototype --ignore-scripts
npm --prefix prototype test
npm --prefix prototype run build:app
BROWSER_EXECUTABLE=/usr/bin/chromium npm --prefix prototype run test:browser
```

ブラウザ検証は必要時だけローカルサーバーを起動し、起動済みなら再利用する。自身で起動したサーバーだけを終了する。検証データ・トークン・応答は全て合成。本番アカウントや実SS案件は操作しない。

## 確認項目

- 本番用ビルドのログイン有無、登録済みTutor callbackへの案内、詳細URLの復帰と直リンク・再読み込み。
- GETの認証ヘッダー、no-store、サンプル／書き込みUIがないこと、検索・完了・並べ替え・旧画面リンク。
- 画面往復、認証初期化1回、戻る／進む、401／403・ログアウト・別タブ・遅延応答・JSON解析中のセッション変更。
- 409／429／5xx・空状態、XSS、スマホ／PC・テーマ・印刷。
- 試作側の未保存編集・キーボード縮小シミュレーションも継続検証。

## 公開前の判断

この変更はdraft PRで親の確認を受ける。マージ・本番入口切替はまだ行わない。将来マージしても `/` は旧ホームのままで `/app/` を個別に確認できる。ロールバックは新入口を使用しない／静的ファイルを前版へ戻すだけで、DB復元は不要。

iPhone実機Safariのキーボード・safe area・ホーム画面追加でのGoogle認証、本番の認証済みGETは公開前後の別検証として残す。合成テストの成功を本番実機確認済みとは扱わない。画像のLibrary転送障害は実装の完了条件にしない。
