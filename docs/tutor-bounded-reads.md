# Tutorの読み取り待機を制限する

旧Tutorは初期化時に学期全体の予定本文を1件ずつ取得してから当日一覧へ進んでいた。後期430予定の合成ケースでは当日の表示に不要な数百リクエストが発生し、応答しない1件を無期限に待っていた。

当日一覧は予定一覧の本文取得から独立して開始する。学期全体から取得するのは回数・前回候補のための予定メタデータだけで、本文は当日と必要な前回予定に限定する。従来形式の前回候補は同一カレンダーの直前同名予定、D1形式は固定ownerの履歴から候補を選ぶ。いずれも候補を最新の予定refで再取得し、既存の帰属比較で照合する。名前からD1所有者を推測しない。

予定一覧は日付・名前を先に表示し、一覧で表示中の日付だけ本文を読む。月間カレンダーは本文の全件取得をしない。読取は共有プールで最大4並列、各読取は待ち行列を含め15秒で停止する。中止を無視する古いPromiseが残ってもpermitは一度だけ解放し、遅い結果を破棄する。Google token取得にも中止シグナルを伝え、失効した共有Promiseを再利用しない。日付・設定・表示世代が変われば古い応答と進捗を捨てる。未取得を「未入力」と表示せず、読込中／失敗／帰属確認を区別する。失敗した当日一覧には編集欄を出さない。

保存処理には読取のtimeoutや並列化を適用しない。未保存の授業予定は既存controllerに保持し、別refで再表示された場合は以前の予定名を付けた保持欄へ隔離して保存を止める。確認テスト・宿題・授業メモのDOM入力も日付移動で保持し、ref/revisionが違う場合は新しい予定の欄へ混ぜない。いずれも自動再送しない。下書きはメモリ内で、ページ離脱時には警告する。

回帰検証は合成データだけで実施する。430件の不要な予定、当日優先、日付高速切替、同名・名称入替、削除、read timeout、保存結果不明、下書き保持を確認する。本番設定・認証・DB・Calendarはこの変更で更新しない。
