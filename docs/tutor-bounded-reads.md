# Tutorの読み取り待機を制限する

旧Tutorは初期化時に学期全体の予定本文を1件ずつ取得してから当日一覧へ進んでいた。後期430予定の合成ケースでは当日の表示に不要な数百リクエストが発生し、応答しない1件を無期限に待っていた。

当日一覧は予定一覧の本文取得から独立して開始する。学期全体から取得するのは回数・前回候補のための予定メタデータだけで、本文は当日と必要な前回予定に限定する。従来形式の前回候補は同一カレンダーの直前同名予定、D1形式は固定ownerの履歴から候補を選ぶ。いずれも候補を最新の予定refで再取得し、既存の帰属比較で照合する。名前からD1所有者を推測しない。

予定一覧は日付・名前を先に表示し、一覧で表示中の日付だけ本文を読む。月間カレンダーは本文の全件取得をしない。読取は共有プールで最大4並列、各読取は待ち行列を含め15秒で停止する。中止を無視する古いPromiseが残ってもpermitは一度だけ解放し、遅い結果を破棄する。Google token取得にも中止シグナルを伝え、失効した共有Promiseを再利用しない。日付・設定・表示世代が変われば古い応答と進捗を捨てる。未取得を「未入力」と表示せず、読込中／失敗／帰属確認を区別する。失敗した当日一覧には編集欄を出さない。

保存処理には読取のtimeoutや並列化を適用しない。未保存の授業予定は既存controllerに保持し、別refで再表示された場合は以前の予定名を付けた保持欄へ隔離して保存を止める。確認テスト・宿題・授業メモのDOM入力も日付移動で保持し、ref/revisionが違う場合は新しい予定の欄へ混ぜない。いずれも自動再送しない。下書きはメモリ内で、ページ離脱時には警告する。

回帰検証は合成データだけで実施する。430件の不要な予定、当日優先、日付高速切替、同名・名称入替、削除、read timeout、保存結果不明、下書き保持を確認する。本番設定・認証・DB・Calendarはこの変更で更新しない。

## 初期化に残る補助サービスの待機

カレンダー一覧・年度・教材などを順番に待ってから当日読取を開始する経路も分離する。当日に必要なのはカレンダー選択設定だけとし、最初から日付と読込状態を表示する。補助サービスは独立して初期化し、設定取得が失敗した場合は未知のカレンダーを読む代わりに明示的なエラーを表示する。学期選択が遅れて無効化された場合は現在選択中の日付で読み直し、古い応答が復元されないよう既存の世代確認を使う。カレンダー一覧にも読取上限時間を適用する。HTMLのmodule参照版も更新し、変更前と同じURLで古いapp.jsがキャッシュされる経路を避ける。

通常のTutor/Homeには、次回の空欄説明へ4見出しを初期化する既存機能がある。prepareのまま通常画面を開く操作は厳密な読み取り専用ではない。移行前の読み取り検証ではhistory画面の読取/target/previewや直接のCalendar読取を使い、通常画面の検証は親指示後のreconcileと未確定処理の照合を済ませてから行う。reconcile/activeのサーバーはテンプレート初期化を拒否する。既存テンプレートの削除や復元はこの変更では行わない。

Cloud側では2026-11-01 08:22:52 UTCに開いた画面が08:38:24 UTCまで当日0件を表示しなかった（15分32秒）。実際に待っていたendpointは観測できていない。回帰テストではカレンダー一覧と教材の応答を保留し、初期日付・当日0件が先に表示されること、仮想16分経過や遅い補助応答でも表示を消さないことを確認する。

初期復元では年度・学期・カレンダー情報を待ってから保存済みの生徒/教室/学期を復元し、その後に予定一覧を1回開始する。教材・目標などの完了は待たない。当日読取は別に先行し、選択IDが同じでも学期の開始/終了日が到着・変更した場合は範囲を整合する。既に新しい範囲で日次読取が開始済みなら重ねず、古い範囲の応答は描画しない。初期化中に本人が選んだ新しい生徒は遅い復元で上書きしない。
